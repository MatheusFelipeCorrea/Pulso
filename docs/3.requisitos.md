# 3. Requisitos

Esta seção descreve os requisitos contemplados nesta descrição arquitetural, divididos em funcionais e não funcionais. Neste repositório serão desenvolvidas **três aplicações**: Web (React), API (Node.js) e app nativo (Flutter). A coluna **Check** rastreia a implementação; a coluna **Status** acompanha o andamento. Tudo parte como pendente.

## 3.1. Requisitos Funcionais

Prioridade na escala **Essencial**, **Importante** e **Desejável**. Plataforma: _web_, _mobile_ ou _web e mobile_ — o mobile é o app Flutter deste monorepo, não um extra. Sprint inicial: **Backlog**.

## 3.3. Restrições Arquiteturais

As restrições impostas ao projeto que afetam sua arquitetura são:

- Neste repositório as três entregas são: **Web (React)**, **API (Node.js)** e **app nativo (Flutter)** — não se admite stack Python/Django neste trabalho.
- Web e Flutter consomem a **mesma API REST** (e o mesmo Socket.IO quando houver tempo real); a regra de negócio não mora no cliente.
- O produto, no escopo da disciplina, é **gratuito** (sem billing).
- Os dados financeiros são **privados do usuário autenticado** (isolamento por conta; conformidade com a LGPD).
- Cotações de moeda usam fonte gratuita com cache — não há feed de tempo real contratado.
- Ficam **fora do escopo**: vale-transporte, relatórios gerenciais de produto, gamificação, cartão/faturas, bots (WhatsApp), modo casal/família, PWA/push, veículos/FIPE, Open Banking e OCR de cupons.
